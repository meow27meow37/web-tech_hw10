# Групповой чат на вебсокете (ДЗ10)

Домашняя работа 10 по веб-технологиям. Одностраничное приложение на React +
TypeScript: регистрация, вход, выход и общий чат, в который могут писать только
авторизованные. Бэкенд предоставлен преподавателем.

Сервер: `https://inai-col3.fishrungames.com`
Чат: `wss://inai-col3.fishrungames.com/chat/`

## Что умеет

- регистрация и вход (те же JWT, что и в ДЗ9);
- общий чат: сообщение видят все, кто сейчас подключён;
- своё сообщение подписано «Вы» и прижато к правому краю;
- видно состояние связи: «подключаемся», «на связи», «связь оборвалась»;
- оборвалась — кнопка «Подключиться заново», пропуск при этом берётся свежий;
- выход закрывает и чат, и сессию.

## Как устроено

| Файл | За что отвечает |
| --- | --- |
| `src/api.ts` | обычные запросы, токены, выдача пропуска для чата |
| `src/App.tsx` | кто вошёл, переключение между входом и чатом |
| `src/Vhod.tsx` | формы входа и регистрации |
| `src/Chat.tsx` | вебсокет, лента сообщений, отправка |
| `src/App.css` | оформление |

## Авторизация

Устроена так же, как в ДЗ9, и подробно описана в его README: **access** живёт
5 минут и лежит только в памяти вкладки, **refresh** лежит в куке `HttpOnly` и
живёт 7 дней, обновление пропуска встроено в запрос (401 → продлить →
повторить один раз), в каждом запросе обязателен `credentials: 'include'`.

Оттуда же перенесены два обхода серверных особенностей: разбор ответа `500` с
HTML вместо JSON при занятом логине и собственная метка выхода, потому что
сервер не стирает куку и не отзывает refresh.

### Почему чат просит пропуск отдельным сообщением

У куки `refresh_token` путь `Path=/api/`, а чат живёт по адресу `/chat/`.
Браузер отправляет куку только по совпадающему пути — значит **до вебсокета она
не доходит**, и представиться кукой чат не может. Поэтому пропуск отправляется
первым же сообщением в сокет, и только после ответа сервера можно писать.

Пропуск берётся **перед** открытием сокета функцией `взятьПропуск()`: если в
памяти пусто (например, после перезагрузки страницы), она сначала продлит его
по куке. Открывать соединение с мёртвым токеном бессмысленно — сервер всё равно
оборвёт связь.

## Протокол чата

Разобран живыми опытами: сервер отвечает только на точные имена, остальное
молча глотает.

| Направление | Сообщение |
| --- | --- |
| мы → серверу | `{"type":"AUTH","payload":{"token":"<access>"}}` |
| сервер → нам | `{"type":"AUTH_SUCCESS","payload":{"username":"..."}}` |
| мы → серверу | `{"type":"CHAT_MESSAGE","payload":{"text":"..."}}` |
| сервер → всем | `{"type":"NEW_MESSAGE","payload":{"sender","text","timestamp"}}` |

Что важно знать, но в документации этого нет:

- **Писать до `AUTH` нельзя**: сервер рвёт связь с кодом **4003 Unauthorized**.
  То есть правило «пишут только авторизованные» держится сервером, а не тем, что
  мы спрятали поле ввода. Проверено отдельно: открыт сокет из консоли и
  отправлено сообщение без входа — разрыв.
- Кривой пропуск — тоже **4003**, но с пояснением `Invalid Token`.
- **Своё сообщение приходит обратно** вместе со всеми, поэтому в ленту руками
  ничего не дописывается: иначе каждое своё двоилось бы.
- **Истории нет.** При подключении сервер ничего не присылает, видно только то,
  что пришло при тебе. Поэтому в пустой ленте об этом написано прямо — чтобы
  пустой экран не выглядел поломкой.
- **Пустой текст** сервер молча глотает, поэтому кнопка «Отправить» гаснет на
  пустом поле и на одних пробелах.
- `timestamp` приходит в миллисекундах.

## Проверено

Прогнано в настоящем браузере (Chromium, Playwright), 12 проверок. Два
пользователя в двух независимых окнах со своими куками: видят сообщения друг
друга, своё подписано «Вы» и не двоится, пустое не отправляется, после
перезагрузки страницы чат сам переподключается и продолжает принимать
сообщения, выход закрывает чат и не пускает обратно по F5. Отдельно проверено,
что сервер обрывает связь на попытке писать без авторизации.

## Запуск

```bash
npm install
npm run dev      # разработка
npm run build    # сборка в dist/
npm run preview  # посмотреть собранное
```

Чат удобно проверять в двух окнах: обычном и приватном (в приватном свои куки,
значит можно войти вторым пользователем).

Публикация на GitHub Pages — автоматически при push в `main`
(`.github/workflows/deploy.yml`). Имя репозитория должно совпадать со строкой
`base` в `vite.config.ts`, иначе страница откроется пустой.
